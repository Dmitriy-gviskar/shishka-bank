6. ЗАКРЫТАЯ ПРИЁМКА И СВЕРКА ПОТЕРЯННОГО ПЕРИОДА
6.1 PIN отсутствует/неверен/детский токен не дают кабинет; правильный PIN работает.
    Recovery по имени не выдаёт код, самопривязка запрещена. Ведущий подтверждает

6.2 На отдельном тестовом аккаунте: пак даёт 7 серверных карт, списывает цену один

    Проверить merge, потерянный ответ, reload, две вкладки, storage failure,
    старый protocol503 и обновление service worker без очистки localStorage.
6.3 Проверить гильдии: founder, join/rejoin без сброса доли, запрет чужой смены ролей,
    распределение остатка выплаты, achievements/history, sleep/awaken.
6.4 Приёмка реализованного recovery-барьера на отдельном тестовом аккаунте:
    - Запросы protocol2 без epoch и со старым epoch к /api/pack/open,
      /api/pack/offline, /api/card/merge получают 503 без финансового изменения.
      Снять fingerprints balance/cards/transactions/receipts до и после отказов.
    - Запрос с новым текущим epoch и новым nonce выполняется один раз; retry
      возвращает тот же receipt без второго списания/выдачи. Тестовые записи учесть.
    - Обновление PWA/handshake/reload не добавляет новый epoch старым queued body;
      503 сохраняет записи, а новая операция поверх очереди иного поколения запрещена.
    - Отсутствующий/невалидный env закрывает карточные операции. Этот негативный
      сценарий проверять на изолированном экземпляре, не меняя уже принятый prod env.
    Не запускать старый API без барьера даже для доступа к отдельному аккаунту.
    Очереди/receipts на устройствах сохранить закрыто, сверять по nonce/истории,
    а не показанному балансу; новый epoch старым body вручную не подставлять.
    Нераспознанные токены после среза разбирать с ведущим, не пересоздавать аккаунты
    автоматически и не удалять localStorage. Legacy-merge остаётся в карантине.
    Ручного UI сверки нет: назначить ответственного и порядок обращения; затронутые
    аккаунты могут оставаться заблокированными, пока остальные проходят приёмку.
6.5 Все компенсации периода после 1 ноября записывать отдельными проверенными
    операциями с основанием; тестовые/фоновые записи вести отдельным журналом.

6.6 Снять checkpoint C1 принятого состояния после сверки, восстановить/проверить
